# the design and the helm's ruling of 2026-09-13.
#
# ⛔⛔ THE ku BUDGETS ARE NOT IN THIS FILE, AND THAT IS DELIBERATE.  A module's Δku
# allowance is its registered RELATIVE ms budget from
# `scripts/kernel_delta_budget.txt`, applied to the module's base ku MEASURED IN
# THE SAME RUN.  Nothing is copied here and no base reading is stored, so there is
# no number in this file that can go stale against that one.
#
# ⚠️ THAT TRANSFER IS A POLICY DECISION, DECLARED, AND NOT A MEASUREMENT.  Those
# percentages were derived as NOISE allowances for a CLOCK.  Applied to a counter
# whose noise is exactly zero (D187: Δku 0 on all five no-op commits, identical on
# two machines) they are LOOSE — and the direction is stated because loose is the
# unpoliced direction.  What would tighten them is a Δku walk over real commits
# PER MODULE, and no such corpus exists: every ku corpus in `docs/` is
# `Tests.Coverage` and nothing else (12 commits x 1 module).  That is D229 §4's
# finding one level down, it is the OPEN ITEM against this file, and it is cheap
# now that a ku reading is SECONDS (X86.Basic 1.8 s, X86.Syntax 3.2 s, measured
# 2026-09-13) rather than the minutes the ms walk costs.

# ── THE ku FLOOR ────────────────────────────────────────────────────────────
# A minimum absolute allowance in UNFOLDINGS, for the same reason the ms budget
# file carries one: a percentage of a small base is not an allowance.
#
# ⛔ AND HERE IT IS NOT A NOISE FLOOR, BECAUSE THERE IS NO NOISE.  The ms file's
# `@floor 6` is "the resolution this box has on a module a percentage cannot
# express".  This instrument's resolution is EXACTLY ZERO — D228's control read
# the same file twice at Δ 0, and D229's constructor plant read Δ 0 twice at N=0.
# So this number is not derived from a spread; it is a POLICY MINIMUM and it is
# labelled as one rather than dressed in a measurement.
#
# The value is the one measured small quantity in this system: the ku instrument's
# own header costs 10 unfoldings (`ku_module_census.py` asserts it every run, and
# refuses if a module's wrapped total is not its unwrapped total plus exactly
# this).  It is the smallest quantity the instrument ever attributes to anything.
#
# ⛔ AND THE CONSEQUENCE I WROTE HERE BEFORE MEASURING IT WAS WRONG, SO IT IS
# CORRECTED RATHER THAN QUIETLY DELETED.  This paragraph read: *"`Tests.VectorRuns`
# has a base ku of 0, so its allowance is this floor and nothing more — the
# tightest cell in the registry."*  **The gate's first real run says its allowance
# is 12, not 10, and the floor does not bind there at all.**  The census reports
# that module's UNWRAPPED ku as 0, but the quantity this gate differences is the
# WRAPPED one, which is 10 — the header — so its budget is 116.9% x 10 = 11.7, just
# above the floor.  ⇒ 🔑 AN EXPLANATION WRITTEN BEFORE THE NUMBER ARRIVES FITS
# WHATEVER ARRIVES, and nothing downstream would ever have tested this one.
# [[feedback-prose-written-before-the-measurement]]
# ⚠️ THE POINT SURVIVES ITS WRONG ARITHMETIC AND IS WORTH KEEPING: measured on the
# first full run, `Tests.VectorRuns` (allowance 12) and `X86.Flags` (33) are the
# two tightest cells in the registry by two orders of magnitude, and
# `Tests.VectorRuns` is GENERATED every batch.  If a batch trips it the first
# reading is INFORMATION — it would be the first evidence that generated vector
# rows carry kernel unfoldings at all — and the answer is to read it, not to raise
# this number.  A gate relaxed on schedule is not a gate (this repository's own
# law, in `kernel_ceilings.txt`'s header).
@floor 10
