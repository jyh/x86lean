## 1. THE CHANGE

- **The rule** (`SoftFloat.roundPack`, `SoftFloat.fmul`) is K4's (D262), with three properties:
  - RC is read as MXCSR's two-bit field, with no inductive;
  - no power above 256 occurs on any path;
  - the flags come out of the same pass as the value.
- **The flags,** from the SDM's MULSD entry ("Overflow, Underflow, Invalid, Precision, Denormal"):
  - PE when the result is inexact;
  - UE when it is also tiny AFTER rounding (D266 §3);
  - OE, always with PE;
  - IE on an SNaN, or on ∞ × 0;
  - DE on a denormal operand when no operand is a NaN.
- **The results:**
  - a NaN: the first source's, quieted, else the second's;
  - ∞ × 0: the QNaN indefinite with its sign bit SET (D265);
  - bits above the scalar lane are kept.
- **The write and its flags are one pair** (`vmulLow`), so the two cannot disagree about the rounding.
- **Two constructors, not an op field:** see D268 §8. B2 (add, sub, div) is where the fold is priced.

## 3. THE VECTORS — SHAPED BY WHAT THE PRE-STATES REACH

Every candidate was classified over the 88 pre-states by `hwprobe/mk_rows.py`'s rule: all 256 register pairs and every
offset −32..+24 from RBX, 1,168 per format. The table is the smallest set writing `xmm0` that reaches every class any
such candidate reaches:
```
  binary64  x1,x0 · x8,x0 (REX.B; opposite signs in 88/88) · 0x10(%rbx) · 0xa(%rbx) · 0x18(%rbx)
  binary32  x1,x0 · x8,x0 · 0x13(%rbx) · 0xd(%rbx) · 0x18(%rbx) · 0x5(%rbx)
```
RC is the state's index mod 4, so every vector meets all four modes. `mulsd %xmm1,%xmm0` is inexact in 68 of 88
states, tiny in 52, and moved by a non-nearest mode in 22.

⛔ **No candidate reaches ±∞, and no state separates tininess before rounding from after.** §4 carries both.

## 4. ⛔ WHERE THE DIFFERENTIAL CANNOT CARRY IT — PINNED IN THE KERNEL

`b1_mulsd_pins` (31 rows) and `b1_mulss_pins` (13 rows) in `Tests/Anchors.lean` run `step` on 44 of `hwprobe/`'s 85
multiply rows. They are generated by `hwprobe/mk_anchors.py` by B0's rule. A row is pinned when:
- x86isa disagrees with it (8): ∞ × 0 at both formats and all four modes. x86isa's indefinite is positive, and both
  processors' is negative.
- or no vector of its format reaches its class (36): an exact product, a tie at nearest, a carry out of the rounded
  significand, overflow at round-up, a binary64 SNaN, tininess before rounding that is not tininess after, an exact
  tiny result, and a preset OE.

**The two processors agree with every row:** an AMD EPYC 7763 and an Intel Core i7-8700B each read `hwprobe/`'s 174 rows
174/174 (D266 §5, D267 §10). Planted wrong once each (the positive indefinite; UE under tininess before rounding), the
two theorems fail, one each. The 44 rows read 51,473 kernel unfoldings.
